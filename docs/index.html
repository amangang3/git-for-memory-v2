MIT AI Studio · Claude Code memory layer

git-for-memory v2: a recorded demo run

A memory layer that learns from Claude Code session logs, keeps every fact versioned in git, checks what it stores against what was actually said, and gives each new session only the memory that belongs to it. Press play to watch one real run, step by step.

The setup

Everything in the demo is fictional and runs in a throwaway folder. Two made-up projects, three short "days" of session logs, and a fresh Claude asked to do the same task under different memories.

1 · Session logWhat the user said, what Claude did, tool output. The .jsonl file Claude Code already writes.
2 · Haiku proposesADD, UPDATE or INVALIDATE a fact, with a quote from the log as evidence.
3 · Code checksIs the quote really in the log? Who said it? The project comes from the folder.
4 · Git storeOne file per fact, one commit per turn. Updates supersede, never delete.
5 · Next sessionGets its project's facts plus user-wide ones. Budgeted, no paths.

Fernway

A fictional Python bookmarking app. The user sets rules here (uv, ruff), later switches to poetry.

Quillpad

A fictional TypeScript editor that uses pnpm. Its memory must never leak into Fernway.

csv-tool

A brand-new empty folder. A fresh Claude sets up a "CSV → JSON CLI with tests" here, with and without memory.

    Run it yourself
    
  
    cd git-for-memory-v2
claude auth status                    # must say loggedIn: true
python3 demo/run_demo.py              # about 3 minutes; --pause to present, --repeats 3 for more runs
open /tmp/gfm-demo/view.html          # browse the memory it built
python3 demo/export_replay.py         # rebuild this page from your own run
    
  
    Needs Python 3.10+, git and a logged-in Claude Code. Nothing to install. It never touches your
  Claude settings, your real sessions or your default memory store.
    

    


    
  
    Honest caveats
    
  
      
    
    • One run per condition. The behaviour table is n=1. Re-run with --repeats 3 before quoting rates.
      • 
    
    • The model blocked the bad inputs first. In this run Haiku already ignored the planted "prefers pip" note and Claude's
      suggestions, so the code trust check had nothing to reject. That check is covered by offline tests.
      • 
    
    • One fact at a time. The hand edit changed the preference to pdm, but a related Fernway fact still says poetry (shown in Act 4).
      • 
    
    • Delivery. Act 5 passes memory with --append-system-prompt. The real SessionStart hook sends the same text as session context.
      • 
    
    • Wording varies. Extraction calls a real model, so another run will word facts differently. The checks test outcomes, not text.
